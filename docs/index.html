📡 Offline-First & Conflict Resolution

Everything works without internet. Data syncs when you reconnect — conflicts are resolved automatically where possible, with a clear UI for true conflicts.

Local-First Storage

  • All data in IndexedDB — reads never hit the network
  • Mutations queued in an operation log
  • Service Worker caches static assets + tiles
  • App loads and functions fully offline

Automatic Sync

  • Reconnects and pushes pending changes
  • FIFO queue with retry and exponential backoff
  • Real-time indicator: pending/synced/offline
  • Pre-cache tiles for an area (bbox + zoom range)

Three-Way Merge

  • Mirrors geogit's merge algorithm
  • FastForward — only one side changed
  • ColumnMerge — different properties → auto-merge
  • Conflict UI for same-property divergence

Conflict UI

  • Side-by-side diff per conflicting property
  • Per-property "Keep Mine" / "Keep Server" toggle
  • Bulk "Keep All Mine" / "Keep All Server" buttons
  • Multi-feature navigation for batch conflicts

Quick Start

# Clone the repo
git clone https://github.com/GeoLang/viewtopia.git
cd viewtopia

# Install dependencies
pnpm install

# Start dev server (port 5174)
pnpm run dev

# Open http://localhost:5174
# Backends are optional — viewer adapts to what's available

# Full platform: clone every repo, then one command for the rest
# (downloads an OSM extract, builds, waits healthy, seeds demo data)
scripts/clone-geolang.sh ~/src/GeoLang
scripts/platform-up.sh

# Or run a single backend: tiletopia (3D Tiles, terrain, analysis)
cd ../tiletopia && cargo run -- serve --port 3000

# Or the AI agent (geolang)
cd ../geolang && python -m uvicorn src.api.server:app --port 8080
